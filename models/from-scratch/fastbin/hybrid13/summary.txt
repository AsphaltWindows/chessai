WHAT CHANGED
- choose_with_compound (every searching player's move: tournaments, arenas, self-games, self-play):
  - log-odds softmax with 0 < T <= 0.05, on a windowable path: windowed_softmax;
  - log-odds argmax on a windowable path: windowed_argmax;
  - everything else exactly as hybrid12: T 0.1, the outcome policies (wld-score and its jitters, which use
    root_outcomes; search labels use expected_outcome), depth 0 and Rand.
- Windowable (Search::windowable, deciding as root_values does): depth >= 2 on the fixed-point search
  (root_values_fx_full: flat LR, probit past depth 2) or the float negamax (trees and DAGs past depth 2, MoE, FM).
  Not the compound path (trees and DAGs at depths 1-2), fastprobit (flat probit at depth 2), depth 1, or NB.
- NB is excluded: its root values at T 0.02 cut only 3-6% of the moves, and the windows' ordering keys cost more than
  that (the first candidate measured ply 2 x1.150, plies 3-5 x0.98-1.03). NB's fixed point carries
  root_windows = false, kept through with_calibration.
- root_values_windowed: the root moves in the order of their static keys (the children's values, best first, ties in
  legal_moves order: the fixed-point keys as the search's depth >= 2 nodes key them, the float eval on the float
  path). The first is searched with a full window, each other with the window (below(best), +inf). best is the
  largest exact value so far; below(b) = b - K T for the softmax (K = 40), the next float below b for the argmax.
  The search is fail-soft, so a value above the window's bottom is exact. A value at or below it is an upper bound:
  at least the move's value, and below the best value. Every exact value has root_values's bits (up to the sign of a
  zero, which no weight, sum or tie depends on).
- softmax_sample_bounded (the softmax's pick from exact values and bounds; the RNG draws exactly once, as in
  softmax_sample):
  - The largest value is an exact one, so each exact move's weight exp((v - max) / T) is softmax_sample's, bit for
    bit.
  - A cut move's true weight lies in [0, hi]. hi is twice its bound's weight (exp needn't be monotone), and at least
    the smallest normal number.
  - Rounded addition and subtraction are monotone in each operand, which gives two facts:
    - If the weights' sum in softmax_sample's order is the same bits with every cut weight at 0 and at hi, it is
      that sum for any true weights, so random_range(0.0..sum) draws the same number.
    - At a cut move the walk reaches with target >= hi and target - hi == target, every weight in [0, hi] leaves the
      move unpicked and the target unchanged.
  - Otherwise the move is searched in full (root_value_of: root_values's own call for that move) and the walk goes on
    exactly. If the sum isn't decided, every cut move is searched in full before the draw, and the pick is
    softmax_sample's own arithmetic. A non-finite value takes that path too: hybrid12's behaviour, whatever it is.
- windowed_argmax: the tied moves (equal to the best value) are exact ones, because every bound is below the best.
  The same ties give the same random_range(0..ties) draw.
- K = 40 was the fastest of 38, 40, 42 and 45 on W4 at plies 3 and 4 (K changes only the speed, any K > 0 is
  exact). CHESSAI_WINDOW_K changes it, for measurements.
- Switches:
  - CHESSAI_WINDOWS=off gives hybrid12's code, for checks.
  - CHESSAI_WINDOW_CHECK=1 also searches every root move in full, and asserts at each windowed search: the exact
    values bit-equal, each bound valid, the weights' sum bit-equal, and the pick equal to softmax_sample's for the
    same draw (for the argmax, the same ties).
  - CHESSAI_WINDOW_STATS=1 prints a WINDOW line a search.
