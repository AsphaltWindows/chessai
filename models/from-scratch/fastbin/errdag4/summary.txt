chessai-errdag4 (2026-11-11, implementation fork; candidates 1 and 2 of the 11-11 ~12:50 performance review)
================================================================================================================

Binary: models/from-scratch/bin/chessai-errdag4, md5 7d6ce9a7bbe53d58eed1652bbe6ce145 (a new file; nothing in bin/
overwritten). Source: fastbin/errdag4-src, a copy of fastbin/errdag-src (chessai-errdag3, md5
261fe1991fab361bc5d75eb428660457) plus errdag4.patch (diff -ru of src/, 492 lines). Built with
nice -n 15 cargo build --release -j 2. errdag2 for reference: 2f963aa0215a9e85bb3d0b9ee07599a0.

What changed (exact: the same operations on the same inputs in the same order)
- Training (candidate 1). Graph::node_output_ctx computes each node's path-independent part once per training step
  and keeps it in the node (Node.base, Node.base_step), then adds the path's cell terms per call:
  CNBP: the three class products before the cells' factors (class_products), then scale_normalise (factors, total
  in class order, divide); LR: predict_log, then the offsets, then softmax; probit: the latent mean and variance
  (latent_base), then (m + mu, var + s2) through probs_of_latent (predict_from_base). Valid within one step: every
  call is inside Bdd::train after begin_step_ctx with the same data, and the node's classifier changes only where the
  existing per-(step, cells) cache is dropped: base_step = 0 is set next to every cache_step = 0 (14 sites:
  delegation.rs 12, bdd.rs 1, pathctx.rs 1). New nodes start with base_step 0. Only for <= 4 classes (3 here).
- Play and training (candidate 2). Cnbp::predict / predict_scaled / class_products run the three class chains in one
  loop; each chain keeps its own order, the total is summed in class order (Rust doesn't contract to FMA).
- Buffers sized to the classes: small_buffer (an 8-entry stack array, a Vec past 8) instead of zeroed [0.0; 256]
  in node_predict_path, descend, predict_training_ctx, route_ctx, train_with_table, train_router_ctx, best_child and
  routing_errors_ctx.
- Not done: hybrid9's single held-out load in own calibration (review's optional extra).

- Without stopping the drivers: League.__init__ reads config.json once per cycle process (repeat.sh runs one cycle
  per process) and `run` never writes it (only create/add do), so config.json was replaced atomically (temp file,
  fsync, os.replace) right after state.json showed a cycle entering its tournament phase; the next cycle reads it.
- error-dag-probit-p1: 13:58:30, during cycle 247's tournament; errdag3 -> errdag4 (tournament binary and the 4 D-P
  lines' train_binary). From cycle 248 every tournament, own calibration (@247 versions on), self-games and D-P
  training ran on errdag4 (tour/tournament.log, owncal/*.arena, self_games.log, runs/D-*.loc.log).
- error-dag-p1: 14:01:27, during cycle 139's tournament; errdag2 -> errdag4 (tournament and the 4 D-L lines). From
  cycle 140 on errdag4, the same logs.
- Both drivers kept completing cycles; no errors in driver.log. The dag_read.sh waiters were left as they were
  (they will read with errdag3/errdag2, their arguments; identical results, slower).
