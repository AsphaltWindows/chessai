WHY 65,536 IS SAFE
- MAX_STATES only decides eligibility: Tables::cells enumerates the route states of a DAG with cells up front and
  returned None (the whole DAG plays in float) past 4,096. Nothing is sized by it: states live in a Vec and an
  index HashMap keyed by (node, sorted marks), ids are u32, and every state keeps its own margin, error bound and
  float fallback (a router decides in fixed point only outside its margin). So every value is the float model's at
  any state count (the argument of hybrid20's MAX_NODES). Memory ~150 B a state: 65,536 states ~10 MB a model;
  enumeration at load takes milliseconds. A cap still bounds pathological DAGs.
- The models that needed it: the warm ply-2 standard's D-P-Ne-ctx-grow lines at v100, std-v1-p2-s1 (82 nodes, 4,756
  route states) and std-v1-p2-s2 (69 nodes, 6,601), which played entirely in float on hybrid20.

UNIT TESTS: 208 lib + 2 main pass (unit-tests.log). New: dags_past_4096_route_states_value_exactly: the real
6,601-state DAG takes the compound path (4,096 < states <= MAX_STATES) and its values equal the float search's bit
