chessai-hybrid17 (2026-11-12, implementation fork; candidates 1 and 2 of the ~06:45 performance review)
=====================================================================================================

What: hybrid16 plus two exact changes. Source: fastbin/hybrid17-src (copy of hybrid16-src); patch: hybrid17.patch
(src/tournament.rs, src/selfplay.rs; Cargo files unchanged). Built with nice -n 15 cargo build --release -j 2 (rustc
1.94.0); the copied tree rebuilt hybrid16's md5 (0cb3d238...) before the edits.
Installed: models/from-scratch/bin/chessai-hybrid17, md5 e4a4fbd4bb104579c942fb654cbf3e11 (cp -n; nothing overwritten).
  1. Rating fits' field search (tournament.rs, Blocks::new -> first_fields): each tournament's set of free variables
     joins the first field that holds it. hybrid16 tested every field's k-wide bitmap (in the global league ~5k fields
     x ~15.2k players, ~75 MB a fit, six fits a cycle). Now each variable keeps the list of fields holding it, in the
     order they were made; a set scans only the fields of its variable in the fewest fields so far, testing containment
     against the field's sorted variable list. Any field that holds the set holds that variable, so the first field
     found is the first field that holds the set: the same fields, field_of and blocks; the floating-point work after
     them is unchanged.
  2. write_round (selfplay.rs -> outcome_text, push_decimal): the feature values' decimal digits go straight into one
     byte buffer with single spaces and a newline a position. hybrid16 built a String per value, a Vec of them and a
     joined line (72 allocations a position: 95.9% of an own calibration's mallocs). Values are u8 (Encoded = [u8; 70]),
     so the bytes are the same by construction.

Saving (CPU = user + sys of the process):
  - Global tournament step, cache off, ABBA: hybrid16 9.12 and 9.29 CPU-s (user 8.21 / 8.36), hybrid17 6.71 and 6.84
    (user 5.97 / 6.09): x0.74, about 2.4 CPU-s a cycle. The quadratic part (all fields per tournament) is gone, so the
    saving grows with history. Wall 7.4 s -> 6.0-8.1 s (load ~11, noisy). sys fell only 0.92 -> 0.75.
  - Own calibration at ply 1: 1.295 -> 1.073 CPU-s a version (x0.83; 13 versions, the binaries alternating).
  - grow-p1b's step (12 round-robins, 1,584 saved games): 5.79 -> 5.03 CPU-s (x0.87).
  - A six-line ply-1 experiment cycle: ~1.3 (own cal) + ~0.7 (tournament) = ~2 of ~16-18 CPU-s (~11-12%). The global
    league: ~2.4 + ~0.4 (two own cals) = ~2.8 of ~15 CPU-s (~19%) a cycle.

Swaps: none (the directive: for new work; swaps are the main session's call). If swapped: change config.json's
tournament binary between cycles (fastbin/hybrid16/swap16.py's procedure). The fit cache keys hold the binary's bytes,
so the first cycle after a swap refits every entry once (~0.12-0.14 s each); arena.py's own-games cache keys on the
binary's md5, so arenas remake own games once. Training binaries are unaffected. The running global league would
cycle faster with it, and so fill the disk faster (the ~06:45 review: ~4-5 days to full).
