What (values-only search, root_values: tournaments, arenas, replay-games/self-games; depth 3 and more)
  1. Trees and DAGs on the compound fixed-point path (<= 64 nodes, log-odds values, the direct path): the search
     keeps the compound state (one compound::Acc per depth, child_into; compound::Changes per move; no encode()).
     A depth-1 node scans its replies' estimates (Compound::reply: value and error bound) in the float search's order
     (hybrid10's captures first when a cutoff is possible): it fails high as soon as an estimate's top v+e <= -beta (returning
     -(v+e)); after the scan, it fails low when alpha > -inf and every bottom v-e >= -alpha (returning -min(v-e));
     otherwise Compound::best values in full only the replies that can be the minimum and runs the float loop in
     order. Keys at depth >= 2 come from the estimates in the exact float order (order_by_bounds: sorted by the
     interval tops; the exact key, Compound::exact_of, only inside groups whose intervals overlap; ties in index
     order; anything non-finite valued in full). Leaves' hashes as hybrid11 (reversible moves only).
  2. Flat probit at ply 3+: the same scan and key order from hybrid8's ln Phi table (fastprobit::estimate / best),
     the same code (leaves_p / leaf_p in place of leaves_c), in hybrid12's staged move order.
  Why exact: fail-soft alpha-beta; each node fails low, is exact or fails high exactly as the float search does,
  with the same exact values, so alpha moves only on the same values and every visited node above the leaves is the
  same; only the bound a failing node returns can differ, and both are valid bounds. Full root windows give
  bit-equal root values (the move order is identical, so even the sign of a zero); hybrid13's windowed roots cut
  the same moves with the same exact values.
  Unchanged: the outcome search (root_outcomes, expected_outcome, outcome, resolve, child, negamax, child_fx
  verbatim; the blocks added to the generic negamax_fx and depth1_from are gated by !OUTCOME: fndiff.txt,
  outcome-gating.txt), depths 1-2, flat LR and NB, FM, MoEs, graphs over 64 nodes (float), Value::Score.
  Switches: CHESSAI_FX_DEEP=off gives hybrid17's search; CHESSAI_FX_CHECK=1 asserts every decision (each bound
  against the float value, each order against the stable sort of the exact keys, root values bit-equal to the
  float / hybrid17 search); CHESSAI_FX_STATS=1 prints "deep fx:" counters.
