WHAT CHANGED
- A cache beside tour/: <league>/scan-cache/games.csv.json (+ games.csv.pairs.json) and game_cpu.csv.json.
- It summarizes the file's complete lines before byte L (L is just after the last "\n"), using the original code's
  own expressions:
  - games.csv: the max round as done_round_robins reads it; the unordered pair counts as contrast_ses counts them,
    in first-seen order; whether every line parses;
  - game_cpu.csv: whether clean_partial would keep every line; the max round;
  - both: the byte offset of each round's first line, and whether the rounds never go down.
- When the cache is trusted:
  - the file is unchanged since the cache was saved (same device, inode, size, mtime and ctime). This holds within
    a cycle and between cycles;
  - or the SHA-256 of bytes [0, L) equals the saved one. This runs once per cycle per file, after the tournament's
    appends.
- What is read then: only the lines after L (and the cache is extended and saved). For game_rows, only the cycle's
  rounds, found from the round offsets.
- Each function runs its original code whenever the summary can't prove the same answer:
  - no cache is possible: a file outside a league's tour/, or a locale encoding other than UTF-8;
  - a "\r" anywhere after L, or bytes that don't decode;
  - a line the original would raise on (or, for clean_partial, drop);
  - rounds out of order (game_rows), or a partial last line (clean_partial);
  - a damaged, foreign or stale cache, or the file changed while being read.
- A partial last line is handled by the original per-line logic in done_round_robins, game_rows and contrast_ses.
- clean_partial: when every row would be kept (the normal case), the file isn't read at all. Otherwise the original
  code runs and rewrites as before.
- Return values, their order, exceptions and every file the original writes are the same. Order here means the dict
  insertion order of the pair counts, and rows in file order. The only new side effect is scan-cache/.
