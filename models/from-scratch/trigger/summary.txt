T4: GRADIENT-DISAGREEMENT SPLIT TRIGGER (2026-11-10, the T4 fork)

Source: models/from-scratch/trigger-src (a copy of fastbin/hybrid6-src; patch scripts in trigger/scripts/).
Binary: models/from-scratch/bin/chessai-trigger (md5 a1775f73356ac873900b7fe8543d63b9). Not deployed anywhere.
Theory: RESULTS.md section 10 item 9, models/from-scratch/theory/summary.txt 6.3 and 9.6.

WHY
Today's rule splits a leaf when its window error stops falling (SplitRule::Worse), which every leaf does as its
learning curve flattens. Theory 6.3: a routed split of leaf theta into theta + d_k on region k changes the loss by
sum_k d_k . G_k to first order, where G_k is the leaf's gradient summed over region k. That is zero when the leaf's
mean gradient is the same in every region the router can make, so the trigger should test that, not stalling.

DESIGN AS BUILT
Option: --split-gradient Z (BDT only; off by default). A leaf splits when the test below gives z > Z, at the end of
each of its windows (today's windows: split_threshold scored examples, num_trained_last), instead of by --split-rule.
--split-gradient-install (needs --split-gradient): the split's router is the probe, already trained, and skips the
hash start. A second factor, for a separate arm only; not tested offline here (a unit test checks it).

Per leaf, while the split limit is not reached:
1. Probe: a router of the tree's --router kind over branch_factor regions, trained on the side, never used to route.
   It learns label-free by today's cluster rule (cluster_pick): its first split_threshold / 5 examples go to a region
   by a hash of the position, later ones to its own pick. Its pick for an example, made before it trains on it, is
   the example's region k.
   Error routing (--route error) uses the same label-free probe. A fresh error target is silent at a split (the
   children are identical copies, theory item 3), so no label-based candidate exists before the split. NB error
   routers route like label-free clustering anyway (U 0.02-0.12, RESULTS section 5) and the probe is a router of
   the same class, so its partition is one an NB router can make. LR error routers route by who is winning (theory
   item 2), a partition not worth rewarding.
2. Gradient: g_i = x_i (outer) (p_i - y_i), with x_i the one-hot features plus a bias in the logistic regression's
   layout (width = 1 + sum of categories), p_i the leaf's training prediction before it trains on the example, and
   y_i the label. For LR leaves this is the gradient of the leaf's own weights. For other leaves it is the gradient
   of a zero-initialised LR correction to the leaf's output, i.e. of an additive region delta (theory item 8).
3. Per window and region: summed gradients G_k[c][j] and use counts n_k[j], the number of region k's examples that
   use weight j (the bias: every example).
4. Window end: keep a_k[c][j] = G_k[c][j] / n_k[j] - G[c][j] / n[j] (region k's mean gradient beyond the leaf's,
   weight by weight; 0 where region k has no uses) and the leaf's per-weight mean. Per-weight centring (the design
   draft centred whole regions): a weight only one region uses gets a = 0, since the leaf can learn it alone. The
   draft's region-level centring let a leaf's still-converging main effects into T.
5. Next window: the test statistic T = sum_k a_k . (G_k - n_k mu), with mu this window's per-weight mean. It is this
   window's region-specific gradients projected on the directions the previous window found: an out-of-sample
   estimate of the first-order loss decrease from moving each child along its own region's direction, beyond moving
   the whole leaf. With no disagreement its mean is 0 (a_k comes from earlier examples and the regions are chosen
   without labels).
6. Standard error clustered by game: each example adds d_i = sum over its weights of a_k (r_i - mu_prev), with
   mu_prev the previous window's per-weight mean (this window's is not known yet), to its game's sum C_g. Var(T) =
   G/(G-1) sum_g (C_g - mean C)^2, z = T / SE. Centring by mu_prev instead of mu adds a per-game term that grows with
   the leaf's drift between windows: it can only inflate the SE, never bias T.
   Game ids: --split-gradient turns on Bdt::scores_rounds, so train and self-play pass each position's game id
   (train: round << 32 | game; the training order is unchanged, the shuffle depends only on the count). A game's
   positions all come in one round, so games are closed at the start of each round (observe_round; measure_seams
   too): an id that recurs in a later round or league cycle is a new game. An example without an id is its own
   cluster.
7. A split is today's (copies, forget_factor, a fresh router with its hash start). The leaf's probe goes; each new
   leaf starts a new probe on its first example. The earliest split is at the end of a leaf's second window, as
   today (today's rule also needs a previous window).
8. At the split limit, probes are dropped (gradient_observe), so nothing accumulates.
9. Cost per example at a leaf: one router prediction and training step, plus two passes over the example's
   (features + 1) x classes weights. State: per leaf the probe, the window's sums and use counts, the previous a and
   mean, and the window's game sums; in the state file only with the option. Model files are unchanged.
10. Logged to stderr at each test: "split-gradient step S leaf L: regions [n_k], games G, T, se, z: split|no split"
   (a leaf's first window: "first window").

Code (trigger-src/src): delegation.rs (params split_gradient / split_gradient_install, printed in the state's
parameter line only when used; Node.probe; struct Probe with state I/O; Graph::gradient_observe, gradient_test,
close_probe_games; check_leaf_split decides by T4 when on; make_delegator drops or installs the probe; state

scores_rounds; tests), main.rs (flags and checks: bdt only, install needs the option, Z finite), bdd.rs and
compound.rs (literals only).

KNOWN LIMITATION
A main effect the leaf has not finished learning, if it correlates with the probe's regions, shows through the
shared weights (the bias, feature values both regions use) as disagreement, though the leaf would learn it without a
split. Per-weight centring removes it for weights one region owns, not for shared ones. It matters most early in a
leaf's life (a new leaf after a split adapts to its region while its probe is partitioning it).
A second, smaller effect: the SE centres each example by the previous window's mean (item 6), so when the leaf moves a
lot between windows (early in its life) the SE is inflated and z understated. Conservative, but it also means z does
not grow with the window as sqrt(n) at a young leaf (below: the root's first test at 1M windows gave z 4.7).
