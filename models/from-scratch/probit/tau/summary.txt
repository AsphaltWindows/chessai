F-P's dynamics tau (2026-11-07). Verdict: a longer memory wins. tau 0 beats the baseline (tau 1e-5) by 85 Elo at equal
CPU at v300, and tau 1e-6 by 63; both clear 40 on both seeds. A larger tau loses 400-560.

Setup: F-P's recipe from scratch (seed 21, 1000 games a round, --vs-previous, --no-games, nice 19, 2 threads) with
--probit-tau, by chessai-probit. The baseline (tau 1e-5) is ../fpfix/FP-base, by chessai-probit4, which reproduced
chessai-probit's F-P-s21 v1-v30 byte for byte; extended to v300 with --resume (run2.sh). The variants run to the
baseline's CPU (cumulative self-play CPU shared out by plies; match.py, extend.sh).
Arenas (arena.sh): d2, both sides calibrated on heldout-lr-d2-s555/round0, the default jitter10 policy, 2 x 1000 games
(seeds 3000+A, 4000+A), the variant as A.

Why tau matters: each position adds tau^2 to the variance of every weight it uses, so the weights' variance settles at
s2 ~ 2 tau. That sets the filter's memory to about 1/(s2 w) positions: ~200k (about a round) at tau 1e-5 and ~20k at
1e-4. At tau 0 the variance keeps shrinking like 1/n, so the model averages over all its data, as a Bayesian should.

Proposal (not deployed), F-P's line plus the tau flag:
  F-P-tau0-c | F-P | models/from-scratch/bin/chessai-probit | scratch | lr | own | --model probit --use-probs --seed 21 --vs-previous --no-games --probit-tau 0
  Its own step needs own_games.binary_by_lineage -> models/from-scratch/bin/chessai-probit, as for F-P-c. The model
  files keep tau, so the own step's train --start trains with it too. The tournament binary is unchanged. The new flag
  gives a new costs signature.
  tau 1e-6 is the hedge if the user worries that tau 0 grows too stiff over the league's 1000+ rounds: it puts a
  floor at s2 ~ 2e-6 (a memory of about 8 rounds), which v300 has not reached yet.

CPU: this check 30.1 min (self-play 1250 s, arenas 557 s). The larger-tau check took about 13.5 min.
